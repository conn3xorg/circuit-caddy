# A small web server on Google Cloud

One `conn3x apply` creates a Compute Engine instance and turns it into a web server: Caddy serving a page over HTTPS, with a certificate from Let's Encrypt, behind two firewalls. You don't need a domain. The site's name is the instance's address under [sslip.io](https://sslip.io), so `34.59.37.78.sslip.io` resolves to `34.59.37.78`, and Let's Encrypt can check it like any other name.

The instance and the software on it are planned, applied and destroyed together, and live in one state file.

## What it builds

On Google Cloud:

- A VPC network and a subnet of its own, so the rules on your project's `default` network, which let SSH in from anywhere, don't apply.
- Two firewall rules: SSH from `admin_cidrs`, and ports 80 and 443 from anywhere.
- An Ubuntu 24.04 instance, `e2-micro` in `us-central1-a` by default, with a 10 GB standard disk and an ephemeral public address.
- An SSH host key for the instance, generated by the `tls` provider and installed by cloud-init. Conn3x checks the instance against it from the very first connection, so you don't need a `known_hosts` entry.
- A user, `conn3x`, made by cloud-init with your public key and sudo. Ubuntu's image on Google Cloud keeps `root` out of SSH, so Conn3x logs in as this user and runs the circuits through sudo. SSH keys added to the whole project are kept off the instance.

On the instance, four circuits:

| Circuit | What it does here |
| --- | --- |
| [circuit-baseline](https://github.com/conn3xorg/circuit-baseline) | chrony, the time zone, a few network sysctls, and key-only SSH. |
| [circuit-hardening](https://github.com/conn3xorg/circuit-hardening) | Tighter SSH crypto and kernel settings. |
| [circuit-firewall](https://github.com/conn3xorg/circuit-firewall) | ufw, denying everything incoming but SSH, 80 and 443. |
| [circuit-caddy](https://github.com/conn3xorg/circuit-caddy) | Caddy, answering on `https://<ip>.sslip.io` with a certificate it fetches itself. |

They run side by side once the instance answers on SSH. The instance doesn't exist when you plan, so the host object says `os = "ubuntu"`, which stands in for the facts the circuits would otherwise read from it.

circuit-hardening turns `log_martians` on, and ufw turns it off again each time it starts, from `/etc/ufw/sysctl.conf`. The two would undo each other and every plan would show a change, so this example leaves it to ufw. To log martian packets, set them to `1` in that file instead.

## Staging first

The certificate comes from Let's Encrypt's [staging server](https://letsencrypt.org/docs/staging-environment/) unless you say otherwise. It works the same way as the real one, but browsers don't trust what it issues, and its rate limits are far higher. That matters here: every new instance gets a new address, so every apply asks for a certificate for a name Let's Encrypt has never seen, and the production server allows only so many a week.

So `curl` needs `-k` and a browser shows a warning. Once you're happy, apply again with `-var staging=false` and Caddy fetches a trusted one.

## Before you start

- Conn3x v0.6.5 or later.
- A Google Cloud project with the Compute Engine API turned on, and credentials that can create instances and firewall rules in it, such as `gcloud auth application-default login`, or a service account key in `GOOGLE_APPLICATION_CREDENTIALS`. The `compute.admin` role is enough.
- An SSH key pair, `~/.ssh/id_ed25519` and `~/.ssh/id_ed25519.pub` by default.

## Cost

An `e2-micro` is $0.0084 an hour, or $6.11 a month, in `us-central1` at [Google's list price](https://cloud.google.com/compute/vm-instance-pricing). The 10 GB standard disk is about $0.40 a month, and the public address $0.005 an hour, about $3.65 a month. That's roughly $10 a month in all, or under 2 cents for an hour of trying it out. Networks and firewall rules are free.

One `e2-micro` and 30 GB of standard disk a month are inside Google's [free tier](https://cloud.google.com/free/docs/free-cloud-features#compute) in `us-central1`, `us-east1` and `us-west1`, so on an account that qualifies you pay for the address only. Everything keeps costing money until you [remove it](#remove-it).

## Run it

```sh
conn3x init
conn3x apply -var project=my-project -var 'admin_cidrs=["203.0.113.7/32"]'
```

Put your own project in `project`, and your own public address in `admin_cidrs`; `curl -4 https://ifconfig.me` shows it. Type `yes` when asked.

The apply took between six and nine minutes when we ran it. Most of that is apt: an `e2-micro` gets a quarter of a core and 1 GB of memory, and the circuits take turns with apt's lock. Run the same `conn3x plan` again afterwards and it says `No changes.`

Then fetch the page:

```sh
curl -k "$(conn3x output -raw url)"
```

```text
Hello from Google Cloud.
```

To see the certificate is the one Caddy fetched:

```sh
ip=$(conn3x output -raw ip)
echo | openssl s_client -connect "$ip:443" -servername "$ip.sslip.io" 2>/dev/null | openssl x509 -noout -issuer
```

The issuer starts `(STAGING)` until you set `staging = false`.

To log in, run the `ssh` output:

```sh
$(conn3x output -raw ssh)
```

It names your key with `IdentitiesOnly`, because circuit-hardening allows four authentication attempts, and an SSH agent with more keys loaded can use them up before it gets to the right one. Your `~/.ssh/known_hosts` doesn't have the instance's key yet, so `ssh` asks you to confirm it the first time. The key it shows is the one in `tls_private_key.host`.

## Make it yours

The page is one `respond` line in the `caddy` module's `sites`. To serve files, give the site a `root` instead and put them there with a step of your own. To proxy to an app, give it `reverse_proxy`. The [circuit-caddy README](../../README.md) has both.

To use your own domain, point its DNS at the `ip` output and replace `local.site` with the name. An ephemeral address changes if you stop and start the instance, though not when you reboot it, so a name you keep wants a [static address](https://cloud.google.com/compute/docs/ip-addresses/configure-static-external-ip-address).

## Remove it

```sh
conn3x destroy -var project=my-project -var 'admin_cidrs=["203.0.113.7/32"]'
```

Type `yes`. This deletes the instance and its disk, the firewall rules, the subnet and the network, which stops the charges. The ephemeral address goes with the instance.

The state file holds the instance's private host key, so delete it as well:

```sh
rm -f terraform.tfstate terraform.tfstate.backup
```

For a server you keep, turn on [state encryption](https://opentofu.org/docs/language/state/encryption/) or store state where you'd store a secret.

## Inputs

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `project` | string | Required | Google Cloud project to create everything in. |
| `admin_cidrs` | list(string) | Required | Addresses allowed to reach SSH, such as `["203.0.113.7/32"]`. |
| `email` | string | `null` | Email address for the Let's Encrypt account. |
| `staging` | bool | `true` | Get the certificate from Let's Encrypt's staging server. Set `false` for a trusted one. |
| `name` | string | `"web"` | Name of the instance, its network, subnet and firewall rules. |
| `zone` | string | `"us-central1-a"` | Zone for the instance. The region comes from it. |
| `machine_type` | string | `"e2-micro"` | Machine type. |
| `labels` | map(string) | `{}` | Labels for the instance and its disk. |
| `ssh_user` | string | `"conn3x"` | User cloud-init creates, with your key and sudo. |
| `ssh_public_key_file` | string | `"~/.ssh/id_ed25519.pub"` | Public key for that user. |
| `ssh_private_key_file` | string | `"~/.ssh/id_ed25519"` | Its private half, which Conn3x logs in with. |

## Outputs

| Name | Description |
| --- | --- |
| `ip` | The instance's public IPv4 address. |
| `url` | The site's address, `https://<ip>.sslip.io`. |
| `ssh` | The command that logs you in. |

## Tested on

Applied with Conn3x v0.6.7 in `us-central1-a`, twice, from an empty state each time: 82 resources, in 5 minutes 41 seconds and in 8 minutes 13 seconds, and the second plan said `No changes.` both times. The instance was up 28 seconds after the apply started; the rest was the circuits. Its host key matched `tls_private_key.host`. `curl -k` on the `url` output returned `Hello from Google Cloud.`, the certificate's issuer was `(STAGING) Artificial Amaranth YE1` from Let's Encrypt, and plain HTTP redirected to HTTPS with a `308`. The `ssh` output logged in as `conn3x`. After a reboot, Caddy and ufw came back, the page was served again with the same host key, and the plan had no changes. `conn3x destroy` removed everything in 1 minute 42 seconds, and `gcloud compute` listed no instances, disks, addresses, firewall rules or networks of the example's left behind.
